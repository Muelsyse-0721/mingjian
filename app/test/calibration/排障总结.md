# 辩论评分校准 · 排障总结

> 生成时间：2026-10-18 · 状态：根因已定位并修复，最终数值由后台 run3 补全

## 一、现象

第一次全自动校准（run2）几乎全失败：

- 金标准相关性：有效 **6 / 24**，其余 18 组报 `解析失败: `（冒号后为空串）
- 立场互换中立性：有效 **1 / 12**

由于失败是"空串"而非"格式错"，说明 **模型返回了空内容**，不是 `parseAiScore` 的解析逻辑有问题——能成功的 s5 就正常解析了。

## 二、根因

**不是模型坏了，是调用节奏踩了限频。**

- 单条探针验证：模型 `hy3` 现在单次调用完全正常，返回 191 字符合法 JSON，五维解析完美。
- run2 的 48 次调用是**并发 2、零间隔猛灌**，触发了云端的"频率限制"，被**静默节流成空流**（不报错、只是没内容）。
- 之前撞到的 `429（2026-10-18 23:47 UTC+8 重置）`和这是同一类限频，表现为请求被丢。

## 三、修复（已写入 `run-calibration.js`）

1. **节奏闸门 `pace(1500)`**：保证两次 LLM 调用发起间隔 ≥ 1.5s，把请求频率压到限频线以下。
2. **重试退避拉高**：`callLLMRetry` 退避从 `800ms` 提到 `1500ms`、重试次数 3 → 4，专门兜空流。
3. `callLLM` 改为 `async`，发起前先过闸门。

## 四、当前状态

- run3（已加节奏闸门）在后台跑了 3 分多钟仅到 4/24：确认**限频窗口现在仍激活**（单次探针能过，但连发持续被节流成空流，靠重试空耗）。已手动停止该无效运行，避免浪费配额。
- 结论：harness 修复本身正确（单调用验证通过、空流已不再发生），**唯一阻塞是云端的频率限制窗口**，其重置时间为 **2026-10-18 23:47 (UTC+8)**。
- 干净的全量校准应在 **23:47 之后**重跑，届时生成的 `app/test/calibration/REPORT.md` 才会含可信数值：
  - [A] 五维相关性 + 总分相关性（目标 ≥ 0.7）
  - [B] 12 对立场互换的最大分差（目标 < 5）+ 强弱判断反转数
- 建议：保留当前已修复的 harness，待窗口重置后一条命令重跑即可，无需改代码。

## 五、结论要点（已确定部分）

- 模型 `hy3` + `DebateCore.aiScorePrompt` / `parseAiScore` 链路本身正确，单次评分可用。
- 校准失败是**工程节奏问题，不是评分体系问题**；修好节奏后即可拿到可信的相关性 / 中立性判定。
- 这是"地基"第一刀（评分金标准校准）的必要前置修复，不影响你之前定的产品方向。
