# 联机玩法扩展（v1.1）：徽章 / 对线房 / 证据站 / 仲裁 / 预期指数

> 2026-10-18 夜间按序交付：③ 赛季徽章与预言家战报 → ① 邀请制对线房 → ② AI 证据情报站 → ⑤ 社区仲裁 → ④ 赔率曲线与预期指数。
> 每个功能都是「纯函数模块（*Core）+ online.js UI 接入 + 测试段 + 部署」四件套，单机版只共用 BadgeCore。

## 一、赛季徽章与预言家战报（js/badges.js，BadgeCore）

- **赛季**：以 `jp_settings` 的 `season` 行为准（`{start, length_days, name}`，默认 2026-10-18 起 90 天），到期自动进下一季（`S1 → S2 → …`）
- **14 枚徽章全部由数据计算**，无额外存储：初试锋芒 / 十搏九想 / 老手入场 / 神预言 / 冷门猎人 / 五连绝世 / 一把回本 / 破产重生 / 有借有还 / 准时先生 / 证据猎人 / 陪审团员 / 对线选手 / 百发百中
- **战报**（我的战绩页）：本赛季投注笔数、胜负、胜率、净积分、最佳/最差单场、连胜纪录、与上季净积分对比
- **天梯榜**：新增徽章列（徽章数）
- 口径：只统计 `kind=bet` 的真实投注行；奖励/质押等非投注行不计输赢（v1.1 统一修正）
- 坑（测试抓出的真 bug）：`placed_at` 是 UTC ISO 串，直接 `slice(0,10)` 在东八区会把赛季首日的投注算进上一天 → 统一走 `localDayStr()` 本地日期

## 二、邀请制对线房（js/debates.js，DebateCore）

- **房间状态机**：`open`（布场中）→ `live`（辩论中）→ `overdue/finished`（超时待揭晓）→ `settled`（已揭晓）
- **轮次制**：每轮双方各一言；一方已发则锁定另一方，防止刷屏；房主可左右互搏（自问自答暖场）
- **邀请码**：4–16 位字母数字，设了就是邀请制房间（列表对无码者隐藏房间内容）
- **AI 五维评分**：论据 / 逻辑 / 针对性 / 增量 / 礼仪各 0–20 分。走云端 LLM（`stream:true`，累加 delta），返回严格 JSON；**LLM 不可用自动降级规则分**（`by='rule'`，证据词频/逻辑连接词/礼仪词启发式），先到先得写入
- **观众押注**：彩池赔率（抽水 5%），平局全额退还；结算时每笔押注**镜像写入 `jp_bets`**（`qid='debate-<did>'`），从而打通现金 / 流水 / 天梯榜 / 徽章
- **下架**：站长可下架房间（`hidden`）

## 三、AI 证据情报站（js/evidence.js，EvidenceCore）

- 每个问题卡内嵌**证据墙**（进行中题 + 已揭晓档案都有）：任何人可提交带链接的公开证据（标题 4–80 字、链接 http(s)、摘要 ≤300 字；无链接时摘要 ≥10 字）
- **社区投票**排序（本机记票防重复）：采纳 > 净票 > 时间；站长采纳/驳回
- **揭晓联动**：问题以 resultOid 揭晓时，被采纳（`status=accepted`）且立场命中的证据：提交者奖 **50 分**（`jp_bets` 里 `kind='bonus'` 镜像 + `evidence.validated=true`）
- **信源质量榜**（天梯榜下）：score = 采纳 ×10 + 揭晓命中 ×20
- **AI 只整理，不制造证据**：云端 LLM 生成中立简报（强弱与缺口），不可用时本地计数兜底（`by='local'`）

## 四、社区仲裁（js/arbitration.js，ArbitCore）

> 定位：已揭晓问题的「异议渠道」。只纠正揭晓结果，不动任何投注记录本身。

- **发起门槛**：问题已揭晓 + **本人押过** + 每问一次（已驳回的允许再发起）+ 同一问题同时只开一个庭
- **投票资格**：任何人，**一票制**，必须质押 10–500 分（`jp_bets` 里 `kind='stake'`、`qid='dispute-<id>'`、`outcome_id=agree|reject`）；发起人不能自投
- **裁决阈值**：≥3 票且同意占比 ≥60% → `upheld`（支持改判）；否则 `rejected`（维持原判）
- **质押结算**（裁决成立瞬间，幂等）：押对边一方按质押占比分走押错边一方的质押；无人押错边则原样退回；余数给质押最大的一方，保证总和守恒
- **站长执行**：`upheld` 的争议在站长台「仲裁队列」执行改判——按新结果**原地重算**全部投注的 status/payout（现金/流水/榜单/徽章自动跟随），争议行记录 `old_result/old_final_odds/new_result/new_final_odds/resolved_by/resolved_at` 全留痕；也可**驳回**（质押全额退回）
- **兜底结算**：裁决成立但投票客户端中断时，任何后续刷新都会补结算（只动仍为 `open` 的质押行）——无单点故障
- **站长直改**：问题管理里已揭晓题也有「改判结果」入口（修正 genuine error 用，不走社区流程）

## 五、赔率曲线与预期指数（js/oddscurve.js，OddsCore）

- **快照写入时机**：建题（开盘即写首个点）、下注（同题 10 分钟节流）、利息池注入（必写）；只对彩池题
- **曲线点位** = 历史快照 + 当前实时池（保证至少一个点）；SVG 纯字符串渲染，题卡内嵌
- **首选项概率** = 该选项池 ÷ 总池（通常是「会/是」）；已为线上 95 个彩池题回填了开盘快照
- **预期指数视图**：全部进行中彩池题的概率墙（由高到低）+ 汇总（题数 / 平均概率 / 高置信 ≥80% / 势均力敌 / 低概率 ≤20%）+ **中性口径文案**（「仅反映平台内投注分布，不构成对任何事件结果的预测或建议」）——固定赔率题由主办方定价，不计入指数
