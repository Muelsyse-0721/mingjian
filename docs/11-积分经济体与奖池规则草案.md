# 明鉴 · 积分经济体与公共奖池规则草案（B 方案）

> 状态：**设计草案，未实现**。本文只定规则、口径与数据结构，不含任何可执行代码。  
> 目标：让「抽水」从"蒸发"变成"有去处"，并给积分建立可持续的**去处（消耗）**&#x4E0E;**价值锚**。

> **决策记录（2026-10-18，已定）**
> - **无赛季**方向：不做赛季重置/软衰减。榜单改为「累计净资产榜（永久）+ 收益率/胜率榜 + 周/月榜」；奖池奖励改为「月榜 / 赛事奖励」，不绑定"赛季清零"。
> - 参数 1（抽水拆分 60% 进池 / 40% 销毁）✅；参数 3（VIP 先上：降抽水 + 提额度 + 多建题）✅；参数 2（赛季衰减）**搁置**。
> - 阶段 1 先做：**抽水进奖池 + 奖池公示 + 站长发放奖励**。

---

## 0. 不变的红线（先钉死）

1. 积分**不可充值、不可提现、不可转让、不可兑换**任何真实货币或等价物。
2. 不做"真*实奖品抽奖"（涉彩票/赌博监管）；抽奖仅限****游戏内积分/装饰品****。*
3. *对外话术****避开****「股票 / 基金 / 分红 / 投资 / 收益」等证券化词汇，统一用「合投 / 联盟 / 奖池 / 赛季基金 / 荣誉」。*
4. *所有涉及"替他人发钱/发奖*"的操作，仅 `is_admin()`（站长）可执行。

---

## 1. 积分经济体总览（四个水龙头 / 四个下水道 / 三个价值锚）

| 环节      | 内容                                       |
| ------- | ---------------------------------------- |
| 水龙头（产出） | 开户赠送、赢盘派彩、证据奖励、赛季奖池发放、商城活动赠送             |
| 下水道（消耗） | 输盘（净转移）、商城购买（销毁）、赛事报名（销毁）、抽奖报名（销毁）、赛季软衰减 |
| 价值锚     | 天梯排名、赛季荣誉、功能特权（VIP）、外部奖品（广告/赞助买单）        |
| 控通胀     | 抽水部分销毁 + 商城/赛事销毁 + 赛季软衰减                 |

**核心原则**：产出 ≈ 消耗。只增不减 → 积分通胀 → 天梯退化成"肝度榜"。

## 2. B · 公共奖池（重点）

### 2.1 钱从哪来

- 沿用现有卡池抽水 `fee`（默认 5%，从赔付池扣除，公式不变）。
- **结算时把扣下的抽水"记账"进公共奖池**，而不是让它消失。
- 拆分参数（可在 `jp_settings.site` 调整）：
  - `rake_to_pool_pct`：抽水中进公共奖池的比例（建议 60%）
  - `rake_burn_pct`：抽水中直接销毁（通缩）的比例（建议 40%）
  - 约束：两者相加 = 100%。

> 计算口径：结算某题时 `rake_amount = 总池 × fee`；其中 `rake_amount × rake_to_pool_pct` 记入奖池，其余销毁（不入任何账户）。

### 2.2 奖池规则

- **公示**：奖池余额对所有人可见（匿名只读）。
- **用途（仅三处，禁止挪用）**：
  1. **赛季排行榜奖励**：赛季结束按天梯前列发放（详见 §5）。
  2. **赛事奖励**：站长发起赛事，设定奖池额度，优胜者分。
  3. **赞助话题成本**：支付赞助位的成本（外部，对外部奖品/赞助商结算，不涉及兑换）。
- **发放**：仅站长可发起，逐笔留痕（`jp_prize_pool_log`），公开可查。
- **防刷**：
  - 赛季榜按**净资产**排名（已实现），一手机一号（已实现），降低多号刷榜。
  - 单赛季个人奖励上限（参数 `season_reward_cap`）。
  - 奖池发放必须关联一个"赛事/赛季/赞助"事件 id，杜绝无名义打款。

### 2.3 数据结构（草案）

```
jp_prize_pool_log
  id            bigserial pk
  ts            timestamptz default now()
  amount        int            -- 正=入池，负=出池发放
  reason        text           -- 'rake' | 'season_reward' | 'event_reward' | 'sponsor_cost'
  ref_qid       text           -- 若来自某题抽水
  ref_event     text           -- 赛事/赛季/赞助 id
  actor_uid     text           -- 发放操作人（发放时）
  meta          jsonb
-- 余额 = sum(amount)，也可在 jp_settings 缓存 balance 便于展示
```

- RLS：anon 可读（公示）；写仅 `is_admin()`。

## 3. 商城（装饰 / 消耗）

### 3.1 规则

- 用积分购买**装饰类**物品：名讳颜色、头像框、主页主题、称号、徽章挂件。
- **购买即销毁积分**（不进奖池、不转给他人）——这是真正的"下水道"。
- 物品**不可转让、不可出售换回积分**（防止变相转账）。
- 支持"限时/限量"制造稀缺与话题。

### 3.2 数据结构（草案）

```
jp_store_items
  item_id       text pk
  name          text
  kind          text          -- 'cosmetic'
  price_points  int
  payload       jsonb         -- 样式参数（颜色值/图标/主题）
  stock         int null      -- null=无限
  active        bool default true
  created_at    timestamptz

jp_store_orders                     -- 已有（05-store.sql）
  id uuid pk, uid, item_id, kind, cost_points, created_at

jp_user_items                       -- 新增：持有关系
  id uuid pk, uid, item_id, acquired_at, equipped bool default false
  unique(uid, item_id)
```

- RLS：目录 `jp_store_items` anon 可读；订单/持有 `jp_user_items` 本人可读写（借用 `is_admin` 无需）。

## 4. VIP 特权（积分 → 更好的体验）

### 4.1 规则

- 用积分购买**VIP 时长**（月/季/年），到期失效；**不可续期转让**。
- 特权（建议先上简单几项）：
  - `fee_discount`：抽水降低（如 VIP 抽水 3%，差额仍按 §2 规则记账）。
  - `loan_limit_bonus`：信用借货额度加成。
  - `max_open_questions`：可同时进行的建题数增加。
  - `arbitration_priority`：仲裁质押展示/受理优先级。
  - `analytics_plus`：高级数据看板 / 历史复盘。
  - `ai_review`：AI 辩论/证据复盘（若已接 LLM）。
- 特权在**发起结算/借款/建题**时读取用户 VIP 状态，动态生效。

### 4.2 数据结构（草案）

```
jp_vip
  uid           text pk
  tier          text          -- 'vip1' | 'vip2' ...
  expires_at    timestamptz
  updated_at    timestamptz default now()
```

- 特权参数集中放 `jp_settings` 的 `vip_tiers`（jsonb），便于调参不改代码。
- RLS：本人可读自己 VIP；写由购买流程（本人 uid）或站长（赠予，可选）。

## 5. 赛季重置与荣誉墙（控通胀 + 长期目标）

### 5.1 规则

- 沿用现有赛季机制（每 `length_days` 天一季）。
- **赛季结束**：
  1. 固化当季排名与关键数据 → 荣誉记录。
  2. 积分**软衰减**（参数 `season_reset_pct`，如保留 50%），或段位重算，避免分数无限累积。
  3. 天梯榜**只统计当季**；历史进"荣誉墙"。
- 荣誉墙展示：赛季名次、称号、徽章、经典战役（最高单场收益等）。

### 5.2 数据结构（草案）

```
jp_season_honors
  id            bigserial pk
  season_id     text
  uid           text
  nickname      text          -- 快照
  rank          int
  net_worth     int
  badges        jsonb
  snapshot_at   timestamptz default now()
```

- RLS：anon 可读（公示荣誉）；写仅 `is_admin()`（赛季结算时写入）。

## 7. 与现有系统的衔接

- **抽水记账**：在 `doSettle`/`settleVote` 结算后，按 §2.1 计算并写 `jp_prize_pool_log`（新增一步，不改赔率公式）。
- **商城**：复用 `05-store.sql` 的 `jp_store_orders`，新增 `jp_store_items`、`jp_user_items`。
- **VIP**：新增 `jp_vip`；特权读取接入 `placeBet`/借款/建题等入口。
- **赛季**：`BadgeCore` 已有赛季统计，赛季结算时写 `jp_season_honors` 并执行软衰减。
- **权限**：奖池/荣誉写入走 `is_admin()`；商城/持有走本人 uid。

## 8. 分阶段落地建议（每阶段可独立上线）

1. **阶段 1（B 最小闭环）**：抽水记账 + 奖池公示 + 赛季排行榜奖励。**投入最小、最先让抽水"有意义"。**
2. **阶段 2**：商城装饰（含 `jp_store_items` / `jp_user_items`），做积分真实消耗。
3. **阶段 3**：VIP 特权（`jp_vip` + 特权接入），提升留存/付费意愿（积分向）。
4. **阶段 4**：赛季软衰减 + 荣誉墙（长期控通胀与身份沉淀）。

---

## 9. 风险清单

- **合规**：全程不可兑换/转让；不碰真实奖品抽奖；话术去证券化。
- **通胀**：若消耗追不上产出，需及时调高 `rake_burn_pct` / 加大 `season_reset_pct`。
- **刷奖**：奖池发放必须关联事件且留痕；赛季榜按净资产 + 单季上限。
- **公平**：VIP 特权只影响体验/效率，**不得影响赔率公平性与他人收益**（避免"付费即作弊"）。
