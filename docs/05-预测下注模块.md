# 预测下注模块（v0.2 新增，v1.0 扩充借贷）

> 参考形态：Polymarket 式预测市场 + 辩论天梯的积分体系。
> 核心规则：**与键政天梯共用同一套积分**——下注花的是天梯总积分，输赢都记入同一个天梯榜。

## 一、玩法概述

1. 每个「问题」有 2-4 个互斥选项（如：会 / 不会），以及一个截止日期
2. 用户用天梯积分对选项下注，获得对应赔率
3. 截止后由主办方「揭晓」结果，中奖投注按赔率获得派彩，未中则投注额归池
4. 一切盈亏进入「个人中心 → 战绩回顾」的积分流水，并汇入天梯总积分

**总积分 = 辩论积分（Σ 发言评分）+ 投注净盈亏（Σ 派彩 − Σ 投注）**

## 二、赔率规则（两种模式）

### 彩池赔率（pari-mutuel，默认）

```
赔率_i = 总彩池 × (1 − 抽水) ÷ 选项_i 彩池
```

- 总彩池 = 模拟公众池 + 所有用户投注；抽水默认 5%
- 赔率随投注分布**动态变化**：一边倒的选项赔率低，冷门选项赔率高
- 下注时显示的「预计赔付」已含自己的投注（与彩池规则一致）
- 揭晓时按最终彩池计算最终赔率，赔付 = 投注额 × 最终赔率

### 固定赔率

- 主办方预先为每个选项设定赔率（小数赔率，1.80 = 押 100 中 180）
- 赔付 = 投注额 × 赔率，不随投注变化

**单机演示说明**：公众池为模拟数据（每个问题预设分布），仅用于让赔率形成机制可见；多人版将替换为真实投注分布。用户自建问题可一键启用模拟公众池。

## 三、结算与流水账

- **揭晓**：单机版由用户作为主办方手动揭晓（confirm 二次确认），不可撤销
- **流水账**（个人中心 → 战绩回顾）：每一笔积分变动一条记录

| 类型 | 金额 | 说明 |
|---|---|---|
| 辩论 | 该条发言最终得分（±） | 评分时写入，重新评分时原条目更新 |
| 下注 | −投注额 | 下注时写入 |
| 派彩 | +投注额 × 最终赔率 | 揭晓中奖时写入 |
| 借款 | +本金 | 借款成功时写入 |
| 还款 | −还款额 | 还款时写入（按罚息/利息/本金分配） |

- 每条流水带「结余」列：按时间顺序累计的总积分，最后一条即当前总积分
- 流水按时间正序累计，测试保证结余自洽（见 app/test/smoke-test.js）

### 联机版新增流水类型（v1.1）

| 类型 | 金额 | 说明 |
|---|---|---|
| 对线房押注 / 派彩 | −质押 / +派彩 | 镜像行进 `jp_bets`（`qid='debate-<did>'`） |
| 奖励 | +50 | 证据被采纳且揭晓立场命中（`kind='bonus'`） |
| 仲裁质押 | −质押 | 仲裁投票质押（`kind='stake'`，结算前计入「在押」） |
| 仲裁派彩 / 罚没 | +分走部分 / 0 | 裁决成立时按站边结算；无人押错边则原样退回 |
| 差额补退 | ±差额 | 改判重算派彩的差额（`kind='adjust'`，预留） |

- 非投注行（bonus/stake/adjust）计入现金与流水，**不计胜场、不入投注 CSV**；质押未结算前计入「在押」，天梯榜净资产与玩家视角一致

## 四、与天梯的打通

- 总积分直接映射八大段位（见 docs/03），下注盈亏会影响段位进度
- 设计意图：辩论赚积分 → 投注表达判断 → 盈亏再回流天梯，形成「表达-预测-复盘」闭环
- 防透支：投注额不得超过当前可用积分（最少 10 分/笔）

## 四·补、信用借贷（v1.0 新增，替代破产补助）

> 定位：游戏内「信用额度」，不是真实借贷——不可充值、不可提现、不可转让，与真实货币无关。任何人、任何状态都可借（含负债中），即时到账。

### 规则表（站长可在后台调全部参数）

| 参数 | 默认 | 含义 |
|---|---|---|
| credit_initial | 300 | 初始信用额度 |
| credit_step | +100 | 每还清一笔加成 |
| overdue_penalty | −200 | 每笔当前逾期扣减 |
| credit_min / credit_max | 100 / 2000 | 额度区间（夹紧） |
| loan_rate | 5% | 一次性利息 = 本金 × 利率，借款时算死 |
| loan_term_days | 7 | 借款期限 |
| loan_late_rate | 1%/天 | 逾期罚息 = 本金 × 日罚息率 × 逾期天（已付可抵） |
| force_min_net | −300 | 破产保护线：净资产低于此值自动核销全部债务 |

### 还款与资产口径

- **还款顺序**：罚息 → 利息 → 本金；随时可还，派彩不自动扣
- **现金** = 初始赠送 + 投注盈亏 + 借款到手 − 已还款
- **净资产** = 现金 + 在押 − 负债；天梯榜按净资产排名（含负债列）
- **破产保护**：净资产跌破 force_min_net 时，全部未清借款自动置为 `written_off`（核销）——债务清零、记录留存、本金仍计现金（钱确实到过账）、额度恢复，玩家可立即重新借款。**不删记录**，保证流水与站长台账可追溯；不存在「输光后既不能投注也不能还款」的死局
- **强平标记**：负债 > 额度 × 1.5 时仅在界面标记，不拦截任何操作（防死局设计）
- **利息池**：全部已收利息 + 罚息归平台池；站长可将其划入任意进行中问题的初始彩池（按选项平均分配），每笔划出记录 qid/金额/时间/操作人

### 数据表（云端，公开账本）

- `jp_loans`：lid / uid / nickname / principal / rate / term_days / due_date / status（open \| repaid \| written_off）/ repaid_principal / repaid_interest / late_fee / created_at / closed_at
- `jp_loan_payments`：lid / uid / amount / principal_part / interest_part / late_part / paid_at

## 六、热点题库（v0.3 新增，v1.0 扩充至 100 题）

### 定位

题库是「问题冷启动」的解决方案：让用户一打开就有东西可押，而不是面对空池子发呆。题目全部是**可验证的未来事实预测**（何时发布、是否落地、数据是否达标），不涉及立场站队。

### 设计要点

- **来源可信但可追溯**：每题标注来源平台与讨论入口（链接指向平台**搜索页**，非抓取自特定页面，避免失效与侵权）
- **判定标准必须写死**：每题 desc 明确「以什么为准」（官方文件 / 收盘数据 / 名单数量），揭晓时不扯皮
- **导入即可改**：导入生成独立副本（新 ID、新公众池），用户可改选项、改截止、直接揭晓
- **不重复导入**：按标题去重，已导入的题显示「已加入」

### 与「自动爬虫」的边界（重要）

当前题库是 **AI 一次性整理的内置静态数据**，不是爬虫：

| 方式 | 法律风险 | 当前决策 |
|---|---|---|
| 手动/AI 整理内置题库 | 低（内容为公开话题的事实预测，附来源链接） | ✅ 已采用 |
| 定时抓取知乎热榜生成题库 | 中（违反用户协议 + 内容合规审核责任） | ⏸ 评估后再上 |
| 自动抓取用户发言做评分 | 高（个保法 + 名誉权） | ❌ 不做 |

后续若升级为「定期更新题库」，应改为：**人工/AI 筛选 + 人工确认后发布**，不做全自动抓取。

### 现有题目分类

科技（22）· 财经（16）· 体育（13）· 娱乐（12）· 社会（9）· 消费（9）· 交通（5）· 教育（4）· 游戏（5）· 自然（3）· 民生（1）· 国际（1），共 100 题；95 题彩池赔率 + 5 题固定赔率，含 3–4 选项的区间题（布伦特原油区间、标普 500 区间、奥运金牌数、新能源车销量、A 股公司数）；截止日期分布在 2026-11 至 2028-01，无过期题。

### 已揭晓档案（v1.0 新增）

结束的问题不删除：大厅「已揭晓档案」页永久留存每道已揭晓题的结果、最终赔率与「我的投注」复盘，作为预测准确率的长期记录。

## 七、合规红线（重要）

- **只押积分，不碰真实货币**——积分不可充值、不可提现、不可转让，这是与赌博划清界限的核心设计
- 问题内容须遵守 docs/01 的合规清单：不涉赌球、不涉现实博彩事件赔率
- 多人版引入真实投注分布前，需完成法务评估
