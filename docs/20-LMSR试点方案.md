# LMSR 份额化试点方案

> 目的：让"平仓"成为可能。彩池数学上做不到（见 docs/19 第二节），必须先把定价换成份额制。
> 本方案只做**灰度试点**，不动存量彩池题。

## 一、模型

LMSR（Logarithmic Market Scoring Rule）：平台当自动做市商，按已售份额定价。

```
成本函数   C(q) = b · ln( Σ e^(q_i / b) )
即时价格   p_i  = e^(q_i / b) / Σ e^(q_j / b)      （Σp = 1）
买入 Δ 份  付 C(q + Δe_i) − C(q)
卖出 Δ 份  收 C(q) − C(q − Δe_i)
```

三个好性质：

1. **价格永远是概率**，加总恒为 1，不需要归一化
2. **平台最大亏损有闭式上界**：`b · ln(n)`，与交易量无关
3. **买卖对称**，卖出即反向操作，不需要对手盘

## 二、参数（用数字定，不拍脑袋）

实测（二元题，初始 50/50）：

| b | 买 20 份滑点 | 买 100 份滑点 | 买 300 份滑点 | 单题最大补贴 b·ln2 |
|---|---|---|---|---|
| 100 | +2.5pp | **+33.2pp** | +49.0pp | 69 分 |
| 300 | +1.7pp | +8.3pp | +23.1pp | 208 分 |
| **500** | **+1.0pp** | **+5.0pp** | +14.6pp | **347 分** |
| 1000 | +0.5pp | +2.5pp | +7.4pp | 693 分 |

**取 b = 500**：典型下注 20–100 分只滑 1–5pp，体验接近"按价成交"；单题最坏补贴 347 分，
在积分体系里可接受（当前初始彩池常见 1000 分）。

三选项及以上：`b·ln(n)`，n=3 时 549 分，仍然可控。

配套硬约束：

| 约束 | 值 | 理由 |
|---|---|---|
| 价格上下限 | 2% / 98% | 防止 1 分钱买 99 份，也防止价格卡死无人能接 |
| 单用户单题持仓上限 | 3000 份 | 防止一人吃掉整条曲线 |
| 补贴熔断 | 用量 ≥ 90% × b·ln(n) | 触发后只允许卖出，不允许买入 |
| 单笔最小 | 10 分 | 与现有 `min_bet` 一致 |

## 三、抽水

按成交额收，费率随概率变化：

```
fee = 成交额 × f × 4p(1−p)      f = 5%
```

| 概率 | 每 100 分成交抽水 |
|---|---|
| 5% | 0.24 分 |
| 25% | 0.94 分 |
| 50% | 1.25 分 |
| 95% | 0.24 分 |

与 Polymarket 的 `C×f×p(1−p)` 同构：中间价抽得多，极端价几乎不抽。好处是**抑制"1% 概率刷量"**——
在彩池里刷极端选项几乎没有成本，这里会被价格滑点自然惩罚。

## 四、数据与代码接缝

不新建表，扩展现有结构（保持账本同源）：

| 位置 | 改动 |
|---|---|
| `jp_questions.mode` | 新增取值 `'lmsr'`（现有 `pool` / `fixed` 不变） |
| `jp_questions.lmsr` | 新 jsonb 列：`{ "q": {"yes": 0, "no": 0}, "b": 500, "subsidy": 0 }` |
| `jp_bets.shares` | 新列：本次成交份额（彩池行留空） |
| `jp_bets.price` | 新列：成交均价 |
| `jp_bets.kind` | 新增 `'buy'` / `'sell'`（彩池仍用 `'bet'`，互不干扰） |

**净资产口径保持不变**：`现金 + 在押 − 负债`，其中在押按**持仓成本**计（不按浮盈）。
理由：按市价计会让排行榜随价格抖动，也给"低买高卖刷净资产"开口子。浮盈只在持仓面板展示。

**破产保护不变**：净资产跌破 `force_min_net` 照样核销借款。买入时校验可用现金，不引入保证金。

## 五、结算

赢家：`份额 × 1 分`；输家：0。
已付成本已在买入时扣除，所以净盈亏 = 派彩 − 成本，直接体现在现金上。

派彩总量上限 = 持仓总份额 ≤ 平台收到的现金 + 补贴，而补贴有 `b·ln(n)` 上界，
**不会出现派彩超发**（彩池里靠池子守恒，这里靠闭式上界）。

## 六、老题怎么办

**试点期不迁移。** 存量题继续走彩池，直到自然结算完。

若将来要迁移，反解公式（softmax 平移不变）：

```
q_i = b · ln(p_i)          p_i = 当前池占比
```

代价：迁移瞬间"在押"要从彩池的"份额"换算成 LMSR 的"持仓"，历史流水会与实际持仓不一致。
所以更稳的做法是**新题新规则，老题老规则**，用 `mode` 分流，永远不迁移。

## 七、回滚

试点题**单独建、单独标记**，出问题只需两步：

1. 后台把该题 `lmsr.locked = true`，禁止新买入（只允许卖出）
2. 严重情况下按当前价格强制赎回全部持仓，题目转 `settled` 并附说明

不影响任何彩池题，也不改全局开关。

## 八、验收指标（灰度一周）

| 指标 | 目标 |
|---|---|
| 买入 100 分的滑点 | ≤ 8pp |
| 单题补贴消耗 | ≤ 400 分 |
| 买卖各有 ≥ 20 笔 | 无异常、净资产可复算 |
| 平仓功能 | 涨了能卖（止盈）、跌了能卖（止损）都跑通 |
| 死局 | 0 例（净资产不为负、破产保护正常触发） |
| 用户反馈 | 至少 3 人明确说"终于能跑了" |

## 十、先做哪一块

**定价核心 + 单元测试**。它是纯函数，不碰数据库、不碰 UI，风险最低，且一旦数字对不上，
后面全是白做。这一步做完就能拿真实参数跑模拟，确认补贴上界与滑点符合预期。
