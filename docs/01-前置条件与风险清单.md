# 前置条件与风险清单

> 结论先行：这个构想**技术上门槛中等，真正的硬门槛是数据来源和法律合规**。而这两点指向同一个启动策略——**MVP 不碰自动爬虫、不公开排名真人，先把评分引擎做对**。

## 1. 数据层：最难的一关

**知乎没有可用的开放 API，反爬很强**（登录墙、滑块验证、频率限制），批量抓取违反知乎用户协议，有账号封禁和法务风险。

**更麻烦的是「对线」**：抓某用户自己的回答，相对容易；抓他在别人回答下的评论/对线历史，要难一个量级（需要逐页爬取他人回答再翻评论）。

**合规层面**：《个人信息保护法》下，抓取他人公开发言并公开展示评分排名，属于处理+使用他人个人信息；「已公开」≠「可任意处置」。

| 数据来源 | 可行性 | 说明 |
|---|---|---|
| 手动导入（粘贴 / JSON） | ⭐⭐⭐ 立即可用 | MVP 首选，零合规风险 |
| RSSHub 公共/自建实例 | ⭐⭐ 不稳定 | 知乎路由常年失效，可自建试试 |
| 自用 Cookie 导出爬取 | ⭐⭐ 灰区 | 仅限本地个人使用，不商用、不分发 |
| 授权合作 / 官方接口 | ⭐ 看缘分 | 最干净但最难 |

**附带决策：天梯需要多人，「收录哪些用户」本身就是合规决策** — 自愿报名制（M1/M2）还是公开抓取（M3，需法务评估）。建议从自愿报名开始。

**结论：把「自动爬取」放到最后一公里，不作为启动前置条件。**

## 2. 评分层：产品的灵魂

- [ ] 明确的评分观：评论证质量，不评立场（见 docs/02）
- [ ] 100 条人工标注的「金标准」样本，校准 LLM（与人工打分相关性目标 > 0.7）
- [ ] 立场中立性测试：同一论证正反立场互换，分差 < 5 分；不达标就改 prompt，不过就不上线
- [ ] 可用的 LLM API + 成本预估（见 docs/04，成本不是瓶颈）

## 3. 游戏层

- [ ] 段位与积分规则成文（docs/03）
- [ ] 防刷机制（同一事件计分条数上限、模板内容检测）
- [ ] **申诉与下架机制** — 被评分人可对单条评分申诉，成立则修正/下架；这是公开排名的前提

## 4. 运营合规（仅当公开上线）

- [ ] ICP 备案 + 国内服务器 + 内容审核对接
- [ ] 时政内容做公开排名在国内有监管下架风险 → 建议先小范围/单机版跑，或定位为「论证能力训练工具」
- [ ] 隐私政策 + 用户协议（明确 AI 自动评分仅供参考，不构成对个人的评价）
- [ ] 名誉权风险控制：匿名化展示、允许下架、不贴立场标签

## 5. 技术

- [ ] 1 名全栈（会写后端 + 懂 prompt 工程）即可起步
- [ ] LLM 成本不是瓶颈（1 万条评分约 ¥20–40，DeepSeek 量级），冷启动的标注和校准才是
- [ ] 存储与队列：PostgreSQL + 任意轻量任务队列即可

## Go / No-Go 速查

| 检查项 | 状态 |
|---|---|
| 评分体系可定义清楚 | ✅ 已成型（docs/02） |
| 能绕过爬虫风险启动 | ✅ 手动导入 |
| 评分可保证立场中立 | ⚠️ 需金标准校准验证 |
| 公开排名真人 | ❌ 暂缓，需法务评估 |
