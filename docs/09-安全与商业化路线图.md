# 明鉴 · 安全与商业化路线图（地基方向总结）

> 回答四个战略问题：电话登录 / 防黑客 / 防人机验证 / 盈利模式。
> 适用架构：联机版 `wbapp_7bwzvH0HlWEBuvX8C9eOlY`，13 张公开账本表（RLS true/true），免登录昵称制。

## 0. 两条不可动摇的线

- **中立线**：评「怎么辩」不评「辩什么」，对政治立场绝对中立。这是产品生死线，也是法律安全线。
- **法律护城河**：积分只在平台内循环，**不可充值 / 提现 / 转让**。一旦积分能换真钱，产品就落入博彩监管区，需要牌照——这是绝对红线。

## 1. 怎么把免登录改成绑定电话登录

走 `cloud.auth` 的**手机短信验证码**登录（passwordless / OTP），不碰密码体系。

1. **登录流程**：用户输入手机号 → 平台下发短信验证码 → 输入验证码 → `cloud.auth` 校验通过，返回带 `uid` 的会话。
2. **身份迁移**：`jp_auth_bindings`（uid ↔ wb_uid ↔ nickname）已为这一步预留。首次登录时把「当前昵称的历史积分 / 借贷 / 投注」迁移绑定到 `auth.uid`，老用户不掉资产。
3. **前端改造**：`online.js` 现在的「免登录昵称」写入路径，整体切到 `onAuthStateChange / getSession` 拿到的 `auth.uid`，并加登录 / 退出 UI。
4. **必需配套（关键）**：写权限从 `RLS true/true` 收紧为 **anon 只读、authenticated 仅能写「自己 uid 的行」**。不收紧，电话登录只是换了入口，黑客仍能直写账本。

## 2. 怎么防止黑客入侵（纵深防御）

当前**最大风险**就是公开账本 `RLS true/true`——任何人都能直接往 `jp_bets / jp_loans` 插假数据。落地顺序：

1. **RLS 收紧**：所有写操作必须 `auth.uid() = 行 uid`，anon 一律只读（治本）。
2. **服务端校验**：余额够不够、是否重复投票、押注归属、`settle_mode` 门禁——这些**不能只在前端拦**，要在 RLS / 云函数里再验一遍，前端传来的数据不可信。
3. **管理动作走服务端**：现在 `admin_token` 在前端广播校验，黑客拿到就能伪造揭晓 / 改派彩。应改成**服务端密钥（edge function / 环境变量）**，前端永远不碰 token。
4. **速率限制**：登录接口 + 下注 / 投票等关键写加频控，挡爆破和刷量。
5. **输入校验 + 防 XSS**：题面 / 昵称长度限制、渲染转义（SDK 参数化查询已防 SQL 注入，但显示层要转义）。
6. **审计 + 监控**：`jp_disputes` 已有审计列，把管理动作也记进去；对账本做异常波动告警（如某 uid 短时间内大量写入）。

## 3. 要搞防人机验证（CAPTCHA）吗

**结论：先不做通用验证码，靠电话身份 + 限频就够了。**

- 电话短信验证码本身就是一个**强反作弊闸门**——批量养号有短信成本，自动化难度远高于 CAPTCHA。
- 之前提的「公投一机一票防刷」，用**电话身份**比 CAPTCHA 更可靠（同一手机号一票）。
- 只有出现明确刷量时，再在**高滥用面**（建题防垃圾、公投投票防买票）叠加轻量 Turnstile。
- 理由：CAPTCHA 伤 UX，而预测市场是轻量休闲场景，过早上验证码会劝退用户。

## 4. 如果想盈利，怎么做（守住「积分不可变现」红线）

**不能做**：积分充值、积分提现、积分二级交易——任一条都会把产品推到赌博监管区。

**可做（红线内）**：

- **装饰性内购（软付费）**：头像框、徽章皮肤、昵称特效、对线房主题——纯 cosmetic，不影响胜负，不碰积分。
- **订阅会员 VIP**：付费解锁高级功能（更多同时在押、历史复盘导出、专属邀请制对线房、AI 辩论评分次数、赛季报告）。会员费是订阅，与积分无关。
- **广告 / 品牌赞助话题**：大厅信息流广告；厂商付费发起预测话题（如新品发布预测）。
- **机构付费发起话题**：媒体 / 研究机构赞助特定预测议题。
- **脱敏聚合数据报告**：卖「市场情绪 / 群体预测准确度」的聚合报告给媒体或研究方（不卖个人数据）。
- **知识付费**：辩论评分体系课程、判断力训练营。

## 5. 落地优先级

- **P0**：`cloud.auth` 登录接入 + RLS 收紧——同时解决「免登录→电话登录」和「关掉最大黑客敞口」，是同一刀。
- **P1**：公投防刷（电话身份）。
- **P2**：评分金标准校准通过（相关性 ≥ 0.7、立场互换分差 < 5）后，LLM 评分才可用于真人对线 / 证据站。
- **P3**：盈利模块等用户量与信任起来后再上，且永远不越「积分不可变现」红线。
