# 明鉴 · v1.3 积分经济体与安全落地说明

> 状态：**已上线**（2026-10-18）。规则草案见 `docs/11-积分经济体与奖池规则草案.md`；本文记录「实际落地」了什么。

---

## 一、安全底线（电话登录 + RLS 收紧）

- **电话登录**（`app/js/auth.js`，cloud.auth 短信验证码）：未登录只能读、不能写；首次登录自动把本机旧 uid 战绩过户到新账号（`migrate_legacy_uid` SECURITY DEFINER RPC，仅能迁到自己名下）。
- **RLS**：13 张表 + `jp_profiles` 全部开启；`anon` 仅可读；`authenticated` 读全站、写仅本人行（`uid` / `creator_uid = auth.uid()`）；站长表（`jp_questions / jp_settings / jp_odds_snaps`）写权限仅 `is_admin()`。
- **管理员唯一化**：`is_admin()` = 是否在 `jp_admin_whitelist`。当前唯一管理员 = 站长本人手机号（具体 uid 记录在云端白名单，不写入公开文档）。非管理员**前端不显示站长台入口**。
- `jp_settings` 对匿名读取排除 `admin_token_hash`。
- **旧数据清理**：未电话绑定的本地旧号（`u-` 前缀）及其下注已删除，只保留电话绑定账号。

## 二、积分经济体（让抽水有去处）

- **公共奖池**：卡池题结算时，抽水的 **60%** 记账进 `jp_prize_pool_log`（其余 40% 销毁通缩），**赔率公式不变**；大厅顶部公示奖池余额。
- **奖池用途**：站长台「公共奖池发放」可手动发放；「月榜发放」按本月已结算投注的**收益榜**、按名次权重自动分配奖池；有「本月已发放」幂等拦截 + 「上月榜待发放」提示。
- 抽水进池比例参数：`DEFAULT_SETTINGS.rake_to_pool_pct = 60`。

## 三、积分商城与 VIP

- **商城**（顶部导航「商城」）：装饰 10 件 + VIP 两档（`vip1` 2000 分/30 天、`vip2` 5000 分/90 天），全部用**积分**购买。
- **扣分形态**：写一条 `jp_bets`（`kind='adjust'`、负 `payout`），与大厅余额、天梯净资产、流水三处口径一致；买后积分消耗，不可退换/转让。
- **换装**：已拥有的装饰可「装备」，同一时间一件（先卸后装）；数据库只授予本人更新 `equipped` 列（列级 GRANT + 行级策略）。
- **VIP 特权**：下注返利（抽水折扣惠及本人，不改全池赔率）、信用借款额度提升、同时建题上限提升。

## 四、建题归属

- `jp_questions.creator_uid`（`08-creator-uid.sql`，按 `jp_profiles` 昵称**保守回填**，重名留空防错记）。
- 建题写入 `creator_uid`；「同时建题上限」按 **uid 计数**（旧数据回退按昵称），改昵称不再能绕过。

## 五、数据表

| 表 | 用途 |
|---|---|
| `jp_profiles` | 昵称档案（uid 主键） |
| `jp_prize_pool_log` | 公共奖池流水（正入池 / 负出池发放） |
| `jp_store_orders` | 积分商城订单 |
| `jp_user_items` | 装饰持有（不可删/不可转卖，仅本人可换装 `equipped`） |
| `jp_vip` | VIP 档位与到期时间 |
| `jp_admin_whitelist` | 管理员白名单（仅站长本人） |
| `jp_audit_log` | 通用写操作审计 |

## 六、运维注意

- **重跑 `06-store-items.sql` 后必须重跑 `09-equip.sql`**：06 会重建该表全部策略，否则换装策略消失、更新影响 0 行（不报错，易误判）。
- 抽水进池比例改 `DEFAULT_SETTINGS.rake_to_pool_pct`（或后续接入 `jp_settings.site` 热调即可，届时需同步 UI）。
- **平台检索自动化**（`app/tools/platform-search.js`）若以 `anon` 身份运行，`settle` 会因 `jp_questions` 仅 `is_admin` 可改而被拒；需以站长身份或服务端身份执行（遗留待处理）。
