## 一、VIP 会员能干什么

VIP 用**积分**购买时长，共有两档。它的作用是提升**你本人**的体验与资金效率，**不改变全池赔率，也不改变其他任何玩家的收益**。

### 1.1 两档权益对照

| 项目 | 明鉴会员（vip1） | 明鉴尊享（vip2） |
| --- | --- | --- |
| 价格 | **2000 积分** | **5000 积分** |
| 时长 | **30 天** | **90 天** |
| 单日成本 | 约 66.7 分/天 | 约 55.6 分/天 |
| 中奖抽水返利 | **20%** | **40%** |
| 默认抽水下实际抽水率 | 5% → **4%** | 5% → **3%** |
| 借款额度加成 | **+300 分** | **+800 分** |
| 信用额度上限（默认设置下） | 8000 → **8300** | 8000 → **8800** |
| 同时建题上限 | 3 → **5 题** | 3 → **10 题** |
| 到期行为 | 自动失效，不续费不扣分 | 自动失效，不续费不扣分 |

### 1.2 每条权益的具体算法

| 权益 | 规则 | 代码依据 |
| --- | --- | --- |
| 抽水返利 | 你**中奖**时，按「中奖本金 × 基础抽水 × 返利比例」把平台少收的抽水退回给你本人 | `VipCore.feeRebateOf(stake, baseFee, vip, now)` |
| 实际抽水率 | 基础抽水 ×（1 − 返利比例）。默认 5% → 会员 4% / 尊享 3%，且只降不升、下限 0 | `VipCore.effectiveFee(baseFee, vip, now)` |
| 借款额度加成 | 在站点配置的 `credit_max` 之上直接加数字，不改变利率、期限与逾期罚分 | `VipCore.loanLimit(baseLimit, vip, now)` |
| 同时建题上限 | 取「基础值 3」与「档位绝对值」的较大者，只升不降 | `VipCore.maxQuestions(3, vip, now)` |

**返利只惠及本人的含义**：命题的 `fee` 是全池共享的，派彩公式对所有玩家完全一致。VIP 的返利是结算时单独记一笔返还给本人的流水（`kind='bonus'`），钱从平台抽水减少的那部分出。所以：

- VIP 玩家不会因为返利而拿到比别人更高的赔率；
- 非 VIP 玩家的派彩、奖池分配、榜单口径都不受影响。

### 1.3 购买、续费与到期

- 只能用积分购买，支付时直接扣减可用积分（口径见 `LoanCore.cashOf`）。
- **续费顺延**：仍在有效期内再次购买，从「当前到期时间」往后加 30 / 90 天；已过期则从购买时刻重新起算（`VipCore.composeVipRow` 的 `fromIso` 参数）。
- **到期不自动续费**，不会产生任何自动扣分；到期即失去特权，已完成的返利不受影响。
- 一人一行（`jp_vip` 以 `uid` 为主键），升档会直接改写档位与到期时间。

### 1.4 不列为权益的两项（重要口径）

`VipCore.TIERS` 里还保留了两个参数：

- `arbitration_priority`（仲裁受理优先级 1 / 2）
- `analytics_plus`（高级看板 / 历史复盘，尊享档为 `true`）

**当前版本没有任何界面或流程读取这两个参数**（`app/js/online.js` 未接线）。因此它们**不计入已生效权益**，商城里也不作为卖点展示。等接入后再更新本表。

## 三、购买与装备规则

### 3.1 购买

- **一件商品只能买一次**：目录里每个 `id` 在 `jp_user_items` 中按 `(uid, item_id)` 唯一，重复购买会被前端拦截，也被数据库唯一约束兜住。
- 一次购买会写三行：
  1. `jp_bets`：扣分流水（`kind='adjust'`、`stake=0`、`payout=-价格`，即负派彩表示扣减可用积分）；
  2. `jp_user_items`：持有关系（`uid + item_id`，`equipped` 默认 `false`）；
  3. `jp_store_orders`：订单留痕（`kind='cosmetic'`、`cost_points`）。
- 扣分口径与大厅余额完全一致，都用 `LoanCore.cashOf`；不会出现「商城扣了、榜单没扣」的两套账。

### 3.2 装备（换装）

- **同一时刻只能装备一件**：名讳颜色、头像框、主题、称号、桌宠皮肤各占一个展示位；桌宠皮肤本身也只保留一件。
- 换装是两步写：**先卸后装**——先把本人所有 `equipped=true` 的行置 `false`，再把目标行置 `true`。中间失败最多变成「什么都没装备」，可重试，不产生资损。
- 服务端只授予了 `equipped` 这一列的 `UPDATE` 权限（`09-equip.sql`），所以前端**不可能**改商品 id 或归属人；试图改 `item_id` / `uid` 会被数据库直接拒绝，这是设计意图。
- 换装只改展示位，不影响已购事实，也不重复扣分。

### 3.3 不可退款、不可转让

- **买后不退**：积分在购买瞬间即被销毁，平台不留可退余额，也没有任何「回售 / 回收 / 换回积分」的接口。
- **扣分成功但发放失败**：不会自动退分（否则就形成了积分回售通道），只留订单痕迹，由运营人工补发。
- **不可转让**：`jp_user_items` 没有 `UPDATE`（除 `equipped`）/ `DELETE` 策略，持有关系不可改、不可删，因此无法转卖、赠送或转移到其他账号。
- **VIP 不可转让、不可叠加给他人**：`jp_vip` 一人一行，策略限定 `uid = auth.uid()`。

## 四、积分红线（重申，不可协商）

1. 积分是**应用内非货币分值**：不可充值、不可提现、不可转让、不可兑换法币或加密货币，也不可与货币互转。
2. 商城只有**单向出口**：积分 → 装饰 / 会员时长，扣了就销毁。
3. 装饰与皮肤**不可转卖、不可回售、不可换回积分**；代码里不存在任何反向函数。
4. 所有商品**纯展示或纯个人效率**：不改变赔率、不改变奖池、不影响其他玩家。
5. 本模块不发起任何支付渠道调用，数据库表里没有收款、余额、法币字段。

## 五、运营改价 checklist

改任何价格或权益时，按顺序改这三处，改完再更新本文表格：

1. `app/js/vip.js` 的 `TIERS`（价格 / 天数 / 特权数值）
2. `app/js/store.js` 的 `VIP_BENEFITS`、`VIP_TIER_CARDS`、`PET_SKINS`（与第 1 步保持一字不差）
3. `app/sql/12-store-pet-skins.sql` 的注释与 `jsonb` 数据（仅在 `jp_store_items` 存在时才真正生效）
