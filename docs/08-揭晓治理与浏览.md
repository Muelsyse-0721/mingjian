# 揭晓治理与浏览（v1.2）：防滥用 + 公投 + 分区筛选

> 2026-10-18 交付。核心诉求：**到期后一般不允许人发起揭晓**（防滥用），主观议题交公投，可搜索事实交平台检索，题库浏览支持分类/排序/筛选。

## 一、三种揭晓方式（jp_questions.settle_mode）

| 模式 | 谁能揭晓 | 适用 | 流程 |
|---|---|---|---|
| `search` 平台检索（默认） | 平台（每日自动检索 + 站长兜底），**用户无入口** | 可网络搜索核实的客观事实题 | 到期 → 「待平台检索」区 → 联网查证 → 按事实结算 |
| `vote` 公投揭晓 | 公众（一人一票多数决） | 主观议题（如「美国 2027 是否会衰落」） | 到期 → 「公投中」区 → 一人一票 → 截止按多数结算，平局全退 |
| `manual` 人工揭晓（legacy） | 任何人可按公开事实发起 | 仅站长可建 | 到期 → 「待人工揭晓」区 → 发起揭晓 |

- 建题表单默认 `search`；`manual` 选项仅站长解锁后可见；公投模式必填 `vote_end`（≥ 投注截止，建议 +7 天）
- 老数据回填：100 道题库题全部置 `search`（均为可验证事实题）

## 二、公投规则（jp_public_votes）

- **一票制**：`unique(qid, uid)`，免登录身份 = 本机 uid；截止前可改票（update choice）
- **窗口**：投注截止（`deadline`）后开放投票，`vote_end` 当天截止；之后任何人可见「按公投结果结算」按钮
- **结果**：票数最高的选项为最终结果；**最高票并列 = 平局**（`result='draw'`）：全部投注按 `payout=stake` 全额退还（不计输赢）
- **无人投票**：不自动结算，题留在公投区显示「无人投票，需人工揭晓」，转人工处理
- **到期兜底结算**：`checkVoteSettles()` 在每次刷新时执行——投票窗口结束且有人投票 → 自动按多数决揭晓（幂等，只动 `status='open'` 的行）。客户端断线不影响结算
- 与彩池赔率的关系：投注在开放期发生、赔率照常；公投只决定**结果**，派彩仍按最终赔率（`settleOdds`）

## 三、平台检索（自动 + 人工兜底）

- **每日 09:00 自动化**（workbuddy 自动化，id `5a42c2d6-…`）：列出到期未揭晓的 search 题 → 逐题 WebSearch 查证判定标准 → 事实明确才结算，存疑跳过并留报告
- **脚本**：`app/tools/platform-search.js`
  - `list`：列出到期未揭晓的平台检索题
  - `settle <qid> <resultOid> --note "依据"`：按线上同口径结算（最终赔率、逐笔派彩、证据奖励 50 分），幂等
- **站长兜底**：站长台「待平台检索 / 待揭晓队列」对 search 题显示「平台检索揭晓」按钮 + AI 判定建议（LLM key 只存本机）
- 纪律：只依据可验证公开事实，不推测不站队；来源矛盾的一律跳过留人工

## 四、大厅分区与浏览

**五分区**（空分区自动隐藏，进行中与档案常驻）：

| 分区 | 条件 |
|---|---|
| 进行中 | 未到期 |
| 待平台检索 | 到期 + `search` |
| 公投中 | 到期 + `vote`（含已结束待结算） |
| 待人工揭晓 | 到期 + `manual` |
| 已揭晓档案 | `status=settled`（永久留存，含证据墙/仲裁记录/赔率曲线） |

**筛选排序工具条**（非档案区）：
- 排序：最新发布 / 热度（投注数×1000 + 奖池）/ 奖池最大 / 最早截止 / 最晚截止
- 截止：7 天内 / 30 天内 / 90 天内 / 今年内 / 明年起 / 无截止
- 分类 chips（带计数）：科技 / 财经 / 体育 / 娱乐 / 社会 / 消费 / 游戏 / 交通 / 教育 / 自然 / 民生 / 国际 / 未分类
- 题卡头部显示分类标签 + 揭晓方式徽章

## 六、已知边界

- 公投防刷依赖免登录身份（一机一票）；换设备/清缓存可重复投票——正式版需 cloud.auth 或设备指纹（见 README 下一步）
- `vote_end` 早于 `deadline` 的脏数据按「无投票窗口」处理（`voteClosed` 双条件保护）
- 懒结算路径（`checkVoteSettles`）不含证据奖励分支（按钮结算路径含）——公投题挂证据的场景极少，如出现以按钮结算为准
