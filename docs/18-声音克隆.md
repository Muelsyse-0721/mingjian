# 桌宠声音克隆（Qwen3-TTS 0.6B）

> 目标：不用「调音高」糊弄，而是**用参考音频真正克隆**出大肥鱼和 Claude 的声音。

## 一、为什么选这个方案（选型记录）

本机：Apple M2 / 8GB 内存 / 20GB 空闲 / 无独显。

| 方案 | 规模 | 结论 |
|---|---|---|
| **VoxCPM2**（OpenBMB） | 2B，官方 4090 约 8GB 显存 | ❌ 8GB 统一内存跑不动（权重 + 激活会疯狂 swap） |
| **GPT-SoVITS v2/v4** | 零样本 5s 参考，M4 CPU RTF 0.526 | ⚠️ 可行但依赖极重（ASR/UVR5/G2PW），装完 4GB+；零样本质量不如微调 |
| **Qwen3-TTS-0.6B-Base** | 0.6B，约 2.4GB | ✅ 选它：官方支持 `generate_voice_clone(ref_audio, ref_text)`，CPU 能跑 |
| Edge TTS（旧方案） | — | ❌ 只能调音高/语速，用户反馈「太尖」，本质是拟合不是克隆 |

关键判断：**2B 模型在 8GB 机器上是伪需求**，0.6B 的克隆 + 正确参考音频，比 2B 跑不动要实际。

## 二、参考音频怎么来（这一步最容易错）

原始素材在 `app/assets/voice-test/`：

| 文件 | 内容 | 归属 |
|---|---|---|
| `clipA.m4a` | 「好冷…谁在门口放了这么多 token」 | **大肥鱼** |
| `clipB.m4a` | 「小克你最好了…」 | **大肥鱼** |
| `fish_context.wav` | 16s **两人对话** | 需要按说话人切分 |

> 曾经把 `clipA` 误判成 Claude，导致音色完全不对。教训：**多说话人音频必须先按时间戳切分再测音高**，整段统计会把两个人混在一起。

切分结果（`tools/refs/`）：

- `fish.wav`：clipB 整段 11.1s
- `claude.wav`：`fish_context.wav` 的 0.15–3.175s + 6.35–11.0s 拼接，7.7s

参考文本（`tools/voice_clone.py` 的 `REF_TEXT`）必须与音频一致，否则克隆会跑偏。

## 三、环境（已装好）

```bash

python3 -m venv tools/tts-venv
tools/tts-venv/bin/pip install torch==2.8.0 torchaudio==2.8.0 -i https://pypi.tuna.tsinghua.edu.cn/simple
tools/tts-venv/bin/pip install --no-deps qwen-tts -i https://pypi.tuna.tsinghua.edu.cn/simple
tools/tts-venv/bin/pip install transformers==4.57.3 accelerate==1.12.0 librosa soundfile einops onnxruntime sox -i https://pypi.tuna.tsinghua.edu.cn/simple
brew install sox   # qwen_tts 的 speech_vq 会 import sox，缺二进制会报 "SoX could not be found"
```

**MPS 不可用**：在当前沙箱里 `MTLCompilerService` 起不来（Broken pipe 断言崩溃），所以强制 CPU
（`--device cpu`）。速度约 **1 句/分钟**，104 句约 1.5 小时。

模型下载走 **ModelScope**（支持 Range，8 线程约 1.1MB/s），不要用 hf-mirror（不支持 Range，
多线程会各下一份、拼不起来）。

## 四、用法

```bash
# 环境自检
PATH=/opt/homebrew/bin:$PATH tools/tts-venv/bin/python tools/voice_clone.py --check

# 两角色各一句 demo
... --demo --seed 4

# 自定义一句
... --text "今天也来押一注？" --voice fish --out /tmp/x.wav

# 全量台词（104 句）
... --pack --seed 4

# 打成网页音色包（wav → m4a + manifest）
python tools/pack_install.py
```

## 五、参数是怎么定的

- **seed**：同一段文本，不同 seed 的输出音高能差 90Hz（实测 244–340Hz），必须锁死。
  最终 seed=4：鱼 316Hz（参考 314）、Claude 273Hz（参考 276）。
- **全包固定 seed**：如果每句用 `seed+i`，音色会在 267–338Hz 之间漂移，听起来像两个人。
- **贪心解码**（`do_sample=False`）更稳但偏平，实测鱼会掉到 250Hz（比 Claude 还低），
  所以最终用「固定 seed + 默认采样」。

## 七、效果量化（说话人识别模型，resemblyzer）

用 `resemblyzer` 提取声纹，算余弦相似度（越接近 1 越像）：

| 角色 | 克隆版 | Edge 版 | 提升 |
|---|---|---|---|
| 大肥鱼 | **0.886**（对参考 A） / 0.772（对参考 B） | 0.662 | +0.22 / +0.11 |
| Claude | **0.825** | 0.524 | +0.30 |

参考段选择实验（生成同一句，看与两段参考的相似度）：

| 用谁当参考 | 对 A | 对 B |
|---|---|---|
| clipA | 0.731 | 0.711 |
| clipB | 0.696 | 0.652 |
| clipB 降噪 | 0.663 | 0.721 |

结论：**鱼用 clipA 当参考更准**（已切换）。

## 八、踩过的坑

1. **必须设 `max_new_tokens`**：模型偶发不吐 EOS，曾生成 13 秒甚至更长的废句。
   按 `字数/3.2 × 12fps × 2.5 + 24` 估算上限。
2. **断点续跑**：pack 会跳过已存在且 >2KB 的文件，中断后重跑不会从头再来。
3. **`rm -rf` 会被安全策略拦**（批量删除需确认）；换参考重渲时用 `mv` 把旧目录移走即可。
4. **相对路径**：早期 `gen()` 里 `out.relative_to(ROOT)` 遇到相对路径会抛异常，已修。

## 九、已知局限

1. **0.6B 的能力上限**：相似度明显好于 Edge 调参，但达不到 2B 模型或微调的水平。
2. **CPU 推理慢**：1 句/分钟，改一句台词要等一会儿。
3. **没有微调**：只做零样本克隆；要让音色更像，需要 GPT-SoVITS 这类少样本微调（1 分钟数据）。
4. **参考音频含背景音**：`clipB` 有轻微环境声，会影响相似度；理想素材是干净单人近场录音。

## 十、语料采集流水线（多角色视频 → 按 AI 分类）

脚本：`tools/voice_harvest.py`

```bash
# 1) 看目录里有什么、缺不缺转写
python tools/voice_harvest.py --scan ~/Desktop/ai-voices

# 2) 把某个视频转写结果存成同名 .txt（AudioTranscribe 的原始输出，格式 "[0:0.15,0:3.17,0] 台词"）

# 3) 切分 + 分类
python tools/voice_harvest.py --media a.mp4 --transcript a.txt --source my_video     --map s0=claude,s1=fish

# 4) 看覆盖情况
python tools/voice_harvest.py --report
```

要点：
- **转写的 speaker id 不可靠对应角色**，自动分类只按关键词打分，**必须人工用 `--map` 校正**一次。
- 呼唤语不能当身份特征：鱼会说「小克」，但说话人是鱼不是 Claude（这是踩过的坑）。
- 输出：`tools/corpus/<ai>/<source>_s<id>_<n>.wav` + `manifest.json`（含起止/时长/F0/能量/原文）。
- 切段用 sox（`trim` + `highpass 70` + `norm -3`），<0.8s 的碎片会丢弃。
