# 链上存证（Anchor Registry）

把「已揭晓题目的结果」锚定到 L2 链上，让任何人都能独立验证：**这题的结果在某时刻存在，且之后未被修改**。

> 一句话边界：**链只做证明，不做资金。** 不托管积分、不接受下注、不发代币。

## 一、它证明什么，不证明什么

| | 内容 |
|---|---|
| ✅ 证明 | 某批次题目的 `(编号, 结果, 结算时间)` 摘要在某区块被写入，此后不可篡改 |
| ❌ 不证明 | 结果本身是否正确。正确性由站点的检索/公投/仲裁流程负责 |
| ❌ 不涉及 | 积分、下注、代币、任何资金 |

这个区分很重要：面试里说「我做了链上结算」会被追问「那预言机问题怎么解决」；说「我做了结果存证，正确性仍由链下流程负责，链只保证记录完整性」——这是站得住的回答。

## 二、架构

```
站点（jp_* 云端表）
   │  已揭晓的题
   ▼
tools/anchor-worker.mjs
   │  1. 取未存证的已揭晓题 → 算 Merkle root
   │  2. gas 上限检查 → anchor(root, count, fromTs, toTs)
   │  3. 写 tools/data/anchor-state.json（幂等）
   │  4. 写 app/chain-anchors.json（前端数据）
   ▼
AnchorRegistry 合约（Base Sepolia 等 L2）
   │  只存 root / count / 时间段 / publisher
   ▼
app/chain.html  ← 浏览器内用 viem 重算并比对 root
app/js/chain-badge.js ← 给题目卡片挂「⛓ 链上存证 #N」
```

### 为什么一批一笔，而不是一题一笔

100 题压成一次 `anchor` 调用，gas 从"每题一笔"降到"每批一笔"。Merkle 证明让每道题仍可单独验证。
代价：前端需要保存每题的 proof（`chain-anchors.json`），文件会随题量增长——MVP 阶段可接受。

### 叶子与树的约定（必须前后端一致）

```
leaf = keccak256(abi.encode(qid, result, settledAt))   // result 是字符串，如 yes/no/draw
父节点 = keccak256(min(左,右) ‖ max(左,右))             // 排序对，无需记录左右
奇数节点原样上提，不复制
```

`contracts/test/CrossLanguage.t.sol` 用的是 **worker 实际算出的 root/leaf/proof**，
在链上逐个验证通过——这是 JS 实现与 Solidity 验证器一致的证据，不是"我觉得一致"。

## 三、运行手册

### 1. 部署合约

```bash
cd contracts
export RPC_URL=https://sepolia.base.org
export PK=0x...            # 部署者私钥（只放测试币）
export PUBLISHER=0x...     # worker 地址
forge script script/DeployAnchor.s.sol --rpc-url $RPC_URL --private-key $PK --broadcast
```

拿到合约地址后，把 worker 地址设为 publisher（若部署者与 publisher 不同，用 `setPublisher`）。

### 2. 先 dry-run

```bash
node tools/anchor-worker.mjs --dry-run
# 输出：本批 N 题、root、时间范围；不写状态、不写前端数据、不发交易
```

### 3. 正式跑

```bash
RPC_URL=... PRIVATE_KEY=0x... REGISTRY=0x... CHAIN_ID=84532 \
MAX_GAS_WEI=500000000000000 \
node tools/anchor-worker.mjs
```

成功后：
- `tools/data/anchor-state.json` 记录 anchorId / qid / leaf / proof / txHash
- `app/chain-anchors.json` 更新（需要重新部署站点才对外可见）

### 4. 定时（可选）

```cron
# 每天 09:20，在自动揭晓之后跑一次
20 9 * * * cd /path/to/project && RPC_URL=... PRIVATE_KEY=... REGISTRY=... /usr/local/bin/node tools/anchor-worker.mjs >> /tmp/anchor.log 2>&1
```

## 四、失败模式（都设计过，不是"应该没事"）

| 情况 | 行为 |
|---|---|
| 链不可用 / RPC 超时 | worker 重试 3 次后退出非 0；**站点不受影响**，角标只是不出现 |
| 重复运行 | `anchor-state.json` 里有 `anchored[qid]`，不会重复上链 |
| 运行中崩溃 | 发送前先落盘 `pending` + txHash，重启后可对账；锁文件 10 分钟过期 |
| gas 暴涨 | `MAX_GAS_WEI` 拦截，直接放弃本批并报错，不会烧钱 |
| 私钥泄露 | publisher 只能写锚定、不能取钱（合约里没有钱）；用 `setPublisher` 一键轮换 |
| 前端拿不到 JSON | 角标静默不显示，不影响任何原有功能 |

## 五、已知局限

1. **重新部署才生效**：`chain-anchors.json` 是静态文件，锚定后需要重新发布站点。
2. **proof 文件会变大**：题量上千后建议改成分批文件或查询接口。
3. **publisher 单点**：worker 私钥泄露只能轮换，不能阻止已发生的错误锚定（但错误锚定无法伪造合法 root）。
4. **没有链上校验结果正确性**：这是设计选择，不是遗漏。
5. **测试网**：当前指向 Base Sepolia，主网部署前需要重新评估 gas 与私钥管理。
