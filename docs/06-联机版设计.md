## 三、到期揭晓：能自动什么，不能自动什么（诚实边界）

**不能全自动**：机器无法独立核实「苹果发没发布折叠屏」这类事实真相。到期后必须有人（或 AI 辅助 + 人确认）按公开事实裁决。

v0.5 实现的自动化分层：

1. **状态自动流转**：`phaseOf()` 判定 `open → expired（到期待揭晓）→ settled`。到期问题自动：禁止下注、卡片高亮（琥珀色）、显示「已到期 N 天 · 待揭晓」、自动进入站长台「待揭晓队列」
2. **数据自动刷新**：30 秒轮询赔率/榜单/流水；`visibilitychange` 切回即刷
3. **AI 辅助判定（半自动）**：站长在站长台配置 OpenAI 兼容接口（Key 只存本机 localStorage，不经过云端、不明文传输），对待揭晓问题点「AI 判定建议」→ 前端直连 LLM → 返回建议选项 + 置信度 + 依据 → **站长人工核对后**一键按建议揭晓。AI 只建议，不自动执行
4. **将来可全自动的**：可编程验证题（行情/收盘类）预留「自动判定源」字段，接行情 API 后机器可直接判定；事实类题仍需人审

## 四、站长控制台（v0.5 核心）

**入口**：顶部导航「站长台」→ 输入口令解锁。

**安全设计**：
- 云端 `jp_settings.admin_token_hash` 只存 SHA-256 哈希（纯 JS 实现见 `js/sha256.js`，与 Node crypto 逐位一致）
- 前端哈希输入后与云端哈希比对；不明文传输、不存原文
- 解锁标记只存本机 localStorage；可一键「锁定站长台」
- 口令可随时在站长台修改（新哈希覆盖旧哈希）

**能力清单**：
| 模块 | 功能 |
|---|---|
| 站内概览 | 玩家数 / 问题三态计数 / 投注笔数 / 总投入总派彩 / 借贷统计（累计放款、未收回本息、逾期、利息池） |
| 待揭晓队列 | 到期问题自动汇集；AI 判定建议；手动/按建议揭晓 |
| 问题管理 | 置顶 / 下架（隐藏，普通玩家不可见）/ 删除（仅无投注题）/ 利息池注入初始池 |
| 全局设置 | 初始积分、默认抽水、全站公告、暂停新投注、维护模式 + **全部借贷规则参数**（额度/步进/罚降/利率/期限/日罚息/破产线） |
| 借贷管理 | 未结清借款表（可核销）+ 最近结束的借款留档（核销/结清记录可追溯） |
| AI 判定配置 | 接口地址 / Key / 模型名（仅本机） |
| 数据导出 | 投注 CSV + 借贷 CSV（含 BOM，Excel 直开） |

全局设置全站即时生效（如改初始积分 → 所有人可用积分立即重算）。

### 信用借贷与破产保护（v1.0 核心）

- **借款**：任何人任何状态可借（含负债中）；额度初始 300、还清 +100、逾期 −200（区间 100–2000）；一次性利息 5%，逾期按本金 1%/天计罚息；还款顺序 罚息→利息→本金
- **破产保护**（`js/loans.js` 之 `isBankrupt` + `online.js` 之 `checkBankruptcy`）：每次写操作后重载数据即检查；净资产 < force_min_net(−300) 时自动把全部未清借款置 `written_off` 核销——**不删记录**（本金仍计现金，流水/台账可追溯），债务清零、额度恢复，玩家立即可以重新借。设计动机：早期版本「强平即禁止投注 + 还款需现金」会造死局（输光后现金 0/负债 315/额度 0，既不能投注也无法还款），已废弃
- **利息池**：`jp_loan_payments` 的 interest_part + late_part 汇总为利息池；站长在「问题管理」按选项平均注入进行中问题的初始彩池，每笔划出写入 `jp_settings.interest_alloc`（qid/金额/时间/操作人）

## 五、身份模型与信任边界（重要）

**免登录昵称制**：uid 随机生成存本机 localStorage，昵称自取（2-12 字），随每笔投注快照进 `jp_bets`。

- 无需注册，打开即玩，冷启动零门槛
- 清缓存/换设备 = 新身份（战绩仍在云端）
- **信任边界：防君子不防小人**。公开写表意味着懂技术的人可伪造他人投注、甚至直接改 `jp_settings`。口令站长台是「功能级」权限，不是「安全级」权限
- **正式版必须接入登录**（cloud.auth 已确认可用：邮箱/手机 OTP、微信、WorkBuddy 账号）：玩家侧可继续免登录，站长侧走真实登录 + RLS 按 `auth.uid()` 校验管理员表，写操作收归本人。这是 v0.6 第一优先项

## 六、数据模型

```sql
jp_questions: qid(UK) title descr mode(pool|fixed) fee deadline status(open|settled)
              result final_odds outcomes(JSONB) pool(JSONB) creator_name from_bank
              pinned BOOL hidden BOOL                      -- v0.5 新增
jp_bets:      qid uid nickname outcome_id stake odds_at_bet status(open|won|lost)
              payout kind(bet|relief) placed_at settled_at
jp_loans:     lid(UK) uid nickname principal rate term_days due_date
              status(open|repaid|written_off)              -- v1.0 新增
              repaid_principal repaid_interest late_fee created_at closed_at
jp_loan_payments: lid uid amount principal_part interest_part late_part paid_at
              -- v1.0 新增；interest_part+late_part 汇总 = 利息池
jp_settings:  key(UK) value(JSONB) updated_at updated_by     -- v0.5 新增
              -- key=admin_token_hash: SHA-256 字符串
              -- key=site: {opening_bonus, default_fee, accept_new_bets,
              --            announcement, maintenance,
              --            loan_enabled, credit_initial, credit_step, credit_max,
              --            credit_min, overdue_penalty, loan_rate, loan_term_days,
              --            loan_late_rate, force_mult, force_min_net, min_bet, min_loan}
              -- key=interest_alloc: 利息池划出记录 [{qid, amount, ts, by}]
              -- key=season: {start, length_days, name} 赛季配置
jp_debates:   did(UK) topic side_a side_b creator_uid creator_name invite_code
              status(open|live|overdue|finished|settled) current_round max_rounds
              deadline hidden result final_odds pool(JSONB) created_at settled_at
jp_debate_posts: did uid nickname side(a|b) round_no content ai_score(JSONB) posted_at
jp_debate_bets:  did uid nickname bet_on(a|b) stake odds_at_bet
                 status(open|won|lost) payout placed_at settled_at
jp_evidence:  eid qid uid nickname side(yes|no|neutral) url title summary
              status(pending|accepted|rejected) votes_up votes_down validated created_at
jp_disputes:  qid uid nickname reason status(voting|resolved|dismissed)
              agree_weight reject_weight created_at resolved_at
              proposed_result old_result old_final_odds new_result new_final_odds resolved_by
jp_dispute_votes: dispute_id uid nickname agree BOOL weight created_at
jp_odds_snaps: qid odds(JSONB) pool(JSONB) created_at   -- 赔率曲线采样（同题 10 分钟节流）
```

- `kind` 现支持 `bet`（投注）/ `bonus`（奖励，如证据命中 50 分）/ `stake`（仲裁质押，`qid=dispute-<id>`）/ `adjust`（差额补退）；非 bet 行计入现金与流水，不计胜场、不入投注 CSV
- `kind=relief` 行 = 早期破产补助（已废弃，保留仅为兼容历史数据），聚合时排除
- `written_off` = 破产保护或站长核销：债务清零、记录留存、本金仍计现金
- 结算由任何人发起：更新问题状态 + 逐笔结算中奖投注 + 批量标记未中
- **改判（仲裁/站长）**：更新问题 result + 按新结果原地重算每笔投注的 status/payout（现金、流水、榜单、徽章自动跟随），仲裁行记录旧→新结果与执行人
- 下架题（`hidden=true`）对普通玩家不可见，站长视角可见并标注
- **已揭晓档案**：`status=settled` 的问题永不删除，大厅「已揭晓档案」页展示结果/最终赔率/我的投注复盘，附证据墙与仲裁记录

## 七、积分规则（联机版）

- 初始赠送 `site.opening_bonus` 分/uid（默认 1000，站长可改）；可用 = 初始 + Σ(派彩 − 投入) + Σ(借款) − Σ(还款)
- 彩池赔率 = 总池 ×（1−抽水）÷ 选项池；总池 = 主办方初始池 + 全场未结算投注
- **净资产** = 可用 + 在押 − 负债；天梯榜按净资产排名（含负债列）
- 破产保护线 `force_min_net`（默认 −300）：净资产低于此值自动核销全部未清借款

## 八、合规红线（继承并强化）

- **只押积分**：不可充值、不可提现、不可转让
- 题库全部为可验证事实预测，不涉立场；揭晓以公开事实为准，过程全站可见
- 联机版不含任何「对真人的言论评分」——这是与单机版的功能分界，也是法律分界
- 站长下架/删除能力即「被投诉内容可处置」的雏形；正式版需补申诉流程

```bash
NODE_PATH=<managed workspace>/node_modules node app/test/online-test.js
# 3. 真实云端 round-trip（十二表读取/插入/更新/删除，跑完自动清理测试数据）
NODE_PATH=<managed workspace>/node_modules node app/test/cloud-roundtrip.js
```

联机测试曾抓出的真 bug：① `withCloud` 之前的 busy 检查导致写后不重载；② `settleOdds` 在揭晓前读不到 `q.result` 算出 0 赔率（上线即全员派彩为 0）；③ 重写 online.js 时三元表达式丢 `: ''` 分支（语法错误被 `node --check` 抓住）；④ **破产保护死局**：原「强平禁止投注 + 还款需现金」使输光玩家（现金 0/负债 315/额度 0）永久卡死——改为自动核销（`written_off`）后消除，且核销不删记录、本金仍计现金，账目不会出现负数；⑤ **赛季时区错位**：`placed_at.slice(0,10)` 取 UTC 日期，东八区赛季首日投注被算进上一天（徽章/战报口径）；⑥ **改判读旧值**：仲裁执行时先更新问题再读 `q.result` 写仲裁留痕，读到的是新值——改为写链前快照；⑦ 证据状态被假库默认值污染（显式传 `status:'pending'`）；⑧ 假数据库缺自增主键映射导致 update 全表匹配。
