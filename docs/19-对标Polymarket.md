# 对标 Polymarket：明鉴的下一步

> 结论先说：**我们缺的不是"功能"，是"可以退出的仓位"。**
> Polymarket 卖的从来不是下注，是**价格发现**；彩池制天然做不到这一点。

## 一、机制差异：不是小号 Polymarket

| 维度 | Polymarket | 明鉴现状 |
|---|---|---|
| 定价 | 中央限价订单簿（链下撮合、链上结算），价格由买卖盘形成 | **彩池**：赔率 = 总池 ÷ 选项池 |
| 仓位 | 份额 0–1，事件发生兑 1 元；**可随时卖出、对冲、提前止盈** | 下注后**锁死到揭晓**，只能等 |
| 费率 | `fee = C × f × p × (1−p)`，中间价最高；做市方 0 费 + 返佣 | 固定抽水 5%，与概率无关 |
| 结算 | UMA 乐观预言机：提案 → 2h 挑战窗口 → 争议交持币人投票，提案/挑战都要押保证金 | `settle_mode`（检索/公投/人工）+ 质押仲裁 |
| 流动性 | 按"贴近中间价的挂单时长"发积分，日结；Sponsored LP | **无做市概念** |
| 建市场 | 任何人提案 + 审核（可验证结果 / 明确信源 / 时间合适 / 公共价值） | 用户可建题，**直接进池，无审核闸门** |

一句话：**他们是市场，我们是赌桌。**

## 二、差距打分

影响 = 对"用户觉得这是个市场"的贡献；成本 = 改动量（S/M/L）。

| 能力 | 差距 | 影响 | 成本 |
|---|---|---|---|
| **提前平仓** | 彩池数学上做不到，需先份额化 | ★★★★★ | L |
| **概率化表达**（赔率 → 隐含概率） | 有快照曲线，但主展示仍是赔率 | ★★★★ | S |
| **建题审核闸门** | 无审核，直接影响题目质量与结算可行性 | ★★★★ | S |
| 动态抽水（按 p(1−p)） | 固定 5% | ★★★ | S |
| 多结果互斥市场（negRisk 简化） | 选项独立，无"概率和=100%"约束 | ★★★ | M |
| 挑战窗口（揭晓后可质疑 24h） | 仲裁只在"已揭晓+本人押过"才可发起 | ★★★ | S |
| 公开只读 API / 分享卡片 | 无 | ★★ | S |
| 仓位组合视图（浮动盈亏） | 只有净资产一个数 | ★★ | M |

## 三、路线

### P0：把"下注"变成"持仓"（一周内）

**1. 提前平仓（核心）——先纠正一个数学陷阱**

彩池里**不存在真正的平仓**。推导：持有一张押注 `S` 的票，若中奖赔付 `S × 总池 × (1−f) ÷ 该选项池`，
而市场隐含概率 `p = 该选项池 ÷ 总池`。两者相乘：`赔付 × p = S × (1−f)`，**恒等于本金扣水**。

实算（押 100 分，A 池 100→400、总池 400→700）：

| 时点 | 概率 | 若中奖赔付 | 期望值 |
|---|---|---|---|
| 买入 | 25% | 380 分 | 95 |
| 池子变化后 | 57% | 166 分 | **95** |

概率涨了，赔付也降了，期望值一动不动。所以"按当前赔率平仓"只能退回 `S × (1−f)`——
**这是后悔药，不是平仓，没有浮盈可锁**。

要实现真正的平仓（能止盈、能止损），必须让仓位有独立价格 → **把彩池改成份额定价**（见 P1-0）。
在那之前，能做的只有下面两件小事：

- **原价退（后悔药）**：揭晓前允许撤回，退回 `S × (1−f)`，池子同步扣减。
  价值有限，但能救"手滑押错金额"，成本极低。
- **反向对冲**：押另一边对冲，锁住亏损上限。用户自己算即可，不需要新功能。

**2. 概率化表达（零成本，先做这个）**

- 大厅卡片：`赔率 3.2x` → `隐含概率 31%`（hover 显示赔率）
- 详情页双显示；曲线纵轴换成概率
- 文案统一："市场认为 31%"，而不是"押 1 得 3.2"

**3. 建题审核闸门**

- 建题写入 `status='review'`，字段强制三选一：可验证结果 / 明确信源 / 截止时间
- 复用 `admin-pending` 队列，加「通过 / 驳回（填理由）」
- 未通过的题不进大厅，但建题人可见状态（避免"发了就消失"）


### P1：让它像市场（两周）

**4. 份额化定价（LMSR）——真平仓的前提**

- 每个选项维护 `q`（已售份额），价格 `p = e^(q_i/b) / Σ e^(q_j/b)`，始终落在 (0,1)
- 买入：付 `C(q+Δ) − C(q)`，`C(q) = b·ln Σ e^(q_i/b)`；卖出即反向，价格天然随市场移动
- 提现 = 份额 × 当前 p，**止盈止损都能实现**，这才叫平仓
- `b` 控制深度：b 越大滑点越小、平台敞口越大 → 按题目初始池设上限（如 b = 总池/10）
- 老题迁移：以池占比作为初始 `p`，反解 `q`，历史流水不动
- 抽水：按成交额 `p(1−p)` 收（与 Polymarket 同构），避免极端价被刷

**5. 多结果互斥市场**：一题多选项且互斥，前端校验概率和 = 100%，加「其他」兜底选项。

**6. 挑战窗口**：揭晓后 24h 内任何人可质疑（需质押，金额随争议次数递增），
   窗口内结果标记为「暂定」，到期自动转「已定」。


### P2：让它被发现（一个月+）

7. **公开只读 API + 分享卡片**：`/api/market/:id.json` + OG 图（题目/概率/成交量）。
   Polymarket 的增长有一半来自"市场页被转发"。
8. **仓位组合视图**：我的持仓、浮动盈亏、已平仓收益、胜率。
9. **排行榜改口径**：从"净资产"改为**预测准确率**（Brier 分数），净资产只作为副榜。
   这才对得起"评怎么辩、不评辩什么"的中立原则——奖励判断力，不奖励梭哈。

## 四、明确不抄

| 不抄 | 原因 |
|---|---|
| 真实资金 / 充值提现 | 法律红线，也是我们"只押积分"的立身之本 |
| 杠杆、做空 | 积分体系下会把破产保护变成常态 |
| 做市返佣现金化 | 无资金流，只能用积分/徽章替代 |
| 链上 USDC 结算 | 已有 `chain.html` 做存证即可，结算留在服务端 |
| KYC / 地区限制体系 | 前提是不碰资金 |

## 五、验收标准

- 平仓：新增回归测试「下注 → 平仓 → 揭晓」，断言**净资产守恒**且池子不超发
- 概率：大厅、详情、曲线的概率同源（同一个 `OddsCore.prob()`）
- 建题：审核通过率、平均审核时长、被驳回理由分布（进审计日志）

## 六、如果只能做一件事

**先做概率化表达，再做份额化。**

概率化只改展示、一天能上，立刻把用户从"赌倍数"拉到"看共识"；
而真正的平仓（止盈止损）必须先有份额价格，那是一次定价引擎的更换，急不来。

顺序：概率化（1 天）→ 建题审核（1 天）→ LMSR 份额化（1–2 周）→ 平仓（份额化之后自然具备）。
跳步会得到一个"能点卖出、但卖了等于退本金"的假功能——比没有更伤。
